# mp-docs — локальное зеркало документации маркетплейсов

Справочник Ozon, Wildberries и Яндекс Маркета, лежащий на диске в markdown и под git.
Нужен потому, что документация маркетплейсов закрыта от серверного IP антиботом,
а во время разработки в неё надо смотреть постоянно.

```bash
bin/mpdocs search "v4/posting/fbs/list"   # найти метод
bin/mpdocs status                          # что есть и когда обновлялось
bin/mpdocs changes --since 1.month         # что маркетплейсы поменяли молча
bin/mpdocs update                          # обновить всё
```

## Зачем именно зеркало, а не поход в сеть каждый раз

1. **Скорость.** `docs.ozon.ru` и `dev.wildberries.ru` отдаются только через
   Camoufox + резидентный канал: ~60 с на страницу. Поиск по зеркалу — миллисекунды.
2. **История.** Площадки правят лимиты и отключают методы без анонсов. Зеркало под
   git превращает это в дифф: `git log -p -- ozon/api/seller/`.
3. **Офлайн.** Канал «дачи» может лежать, туннель — отвалиться. Справочник от этого
   не зависит.

## Что откуда берётся

| Источник | Механика | Цена обновления |
|---|---|---|
| **Ozon Seller API** | `docs.ozon.ru/api/seller/` — это Redoc, спека OpenAPI приходит одним XHR (~4 МБ, 460+ методов). HTML не парсится вообще. | ~1 мин |
| **База знаний Ozon** | `seller-edu.ozon.ru`: текста в DOM нет, статью отдаёт `document-manager` API вместе со списком детей. Обход дерева и получение текста — один и тот же запрос. | ~10 мин |
| **Wildberries** | 13 разделов `/docs/openapi/*`, в каждом спека лежит инлайном в `const __redoc_state` внутри страницы. | ~5 мин |
| **Яндекс Маркет** | Антибота нет. У каждой страницы есть markdown-двойник (`.md`), список всех — в `llms.txt`. Спека OpenAPI — в официальном репозитории на GitHub. | ~3 мин |

Разделы WB и корневые разделы базы знаний Ozon **не зашиты в код**, а вычитываются
на каждом прогоне: появится новый — попадёт в зеркало сам.

## Устройство

```
bin/mpdocs              лаунчер (сам находит python с camoufox)
scripts/
  common.py             пути, frontmatter, запись «только если изменилось», git
  render_openapi.py     OpenAPI → markdown, по файлу на метод
  bundle_openapi.py     сборка многофайловой спеки (ЯМ) в одну
  src_ozon_api.py       спека Seller API
  src_ozon_kb.py        обход seller-edu
  src_wb.py             13 разделов WB
  src_ym.py             справка + спека ЯМ
  mcp_server.py         MCP поверх зеркала (для Cursor и других клиентов)
  mpdocs.py             CLI
mirror/                 само зеркало — ОТДЕЛЬНЫЙ git-репозиторий
state/                  кеши обхода, чекаут спеки ЯМ (не в git)
```

`mirror/` — отдельный репозиторий намеренно: в его истории только изменения
документации, без правок качалок. Иначе `git log` бесполезен.

`fetched_at` не участвует в сравнении содержимого — иначе каждый ночной прогон
давал бы дифф по всем файлам.

## Как этим пользуются

- **Claude Code** — через скилл `~/.claude/skills/mp-docs`, подхватывается сам.
- **Другие клиенты** — через MCP-сервер: `claude mcp add mp-docs -- <python> scripts/mcp_server.py`.
  Инструменты: `search_docs`, `read_doc`, `find_method`, `recent_changes`.
- **Руками** — `rg` по `mirror/`.

## Обновление по расписанию

`mp-docs-update.timer` — ежедневно в 03:30 (±20 мин). Время выбрано до утреннего
окна антибота Ozon (06:00–10:00) и мимо утренней партии `fbs-hub`. Лог —
`/root/logs/mp-docs.log`.

## Ограничения

- Camoufox на машине один, под общим flock с `ozonpos` и воркерами накрутки.
  Пачками зеркало не обновлять, параллельные прогоны не запускать.
- Канал `optic :28081` общий с `ozonpos` — между запросами стоит пауза (`--delay`).
- Канал `4g :28080` принадлежит воркеру накрутки, зеркалу он не нужен.
- Markdown метода — читаемый срез с ограничением глубины вложенных схем.
  Спорные детали сверять с `spec.json` рядом.
