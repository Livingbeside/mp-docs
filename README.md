# mp-docs — локальное зеркало документации маркетплейсов

Справочник **Ozon Seller API, Wildberries, Яндекс Маркета и Uzum Market** на диске: 2300+ markdown-файлов
под git. Нужен потому, что документация маркетплейсов закрыта антиботом (с серверного IP
`docs.ozon.ru` и `dev.wildberries.ru` отдают капчу), а во время разработки в неё надо
смотреть постоянно. Поиск по зеркалу — миллисекунды и без сети.

| Раздел | Файлов | Что внутри |
|---|---|---|
| `ozon/api/seller` | 493 | Seller API: метод = файл, плюс сырая спека `spec.json` (460+ методов) |
| `ozon/kb` | 716 | база знаний seller-edu: регламенты, тарифы, габариты, лимиты FBO/FBS |
| `wb` | 532 | Wildberries: 13 разделов OpenAPI |
| `ym` | 405 | Яндекс Маркет: Partner API + справка |
| `uzum` | 65 | Uzum Market: Seller API (38 методов) + инструкция для продавцов |

## Установка

```bash
git clone https://github.com/Livingbeside/mp-docs.git ~/mp-docs && ~/mp-docs/install.sh
```

Скрипт склонирует зеркало (~44 МБ, отдельный репозиторий → `mirror/`), поставит скилл
в `~/.claude/skills/mp-docs/` с подставленными путями и, если найдёт CLI `claude`,
подключит MCP-сервер. Нужны `git`, `python3` и `ripgrep`.

Ставить можно в любой каталог — пути внутри вычисляются от расположения репозитория.

## Как пользоваться

```bash
bin/mpdocs search "v3/posting/fbs/list"    # найти метод
bin/mpdocs search "лимит" -g 'ozon/**'     # искать только в Ozon
bin/mpdocs status                          # что есть и когда обновлялось
bin/mpdocs changelog                       # что маркетплейс объявил сам
bin/mpdocs changes --since 1.month         # что реально изменилось, включая необъявленное
rg -n "нужная строка" mirror/              # или просто грепом
```

**Агенту** (Claude Code, Cursor, Codex) отдельная инструкция не нужна: `install.sh` кладёт
скилл, и он подхватывается сам. Текст скилла — [`skill/SKILL.md`](skill/SKILL.md):
что где лежит, чем `changelog` отличается от `changes`, когда сверяться со `spec.json`.
Клиентам без поддержки скиллов — MCP-сервер `scripts/mcp_server.py`, инструменты
`search_docs`, `read_doc`, `find_method`, `recent_changes`, `announced_changes`.

## Обновление

```bash
git -C mirror pull
```

Машина-источник обновляет зеркало каждую ночь и сама пушит его сюда, так что
`git pull` всегда приносит вчерашний срез. Чтобы не помнить об этом руками:

```bash
./install.sh --auto-update      # ежедневный git pull через crontab
```

Без этого копия отстаёт молча — поэтому `mpdocs status` начинает ругаться, если
зеркалу больше трёх дней.

Скачать документацию самому (`bin/mpdocs update`) получится, только если рядом есть
Camoufox и резидентный IP: Ozon и WB отдают её исключительно браузеру. Исключения —
Яндекс Маркет и спека Uzum, они качаются напрямую: `bin/mpdocs update ym uzum-api`.
Инструкции Uzum (`uzum-kb`) нужен Camoufox, но резидентный IP — нет.

На самой машине-источнике пуш включается переменной `MP_DOCS_PUSH=1` (у нас — в юните
`mp-docs-update.service`). По умолчанию он выключен: копия без прав на запись иначе
билась бы в чужой `origin` каждую ночь.

### Сводка «что нового» в Telegram

После обновления `mpdocs update` сам присылает в Telegram, что нашлось: новые записи
в журналах площадок, новые, убранные и устаревшие методы (по спекам,
с пометкой «без анонса», если в журнале о них ни слова), правки справки и базы знаний
с фрагментом «было → стало». Если нашёлся только шум, сообщения нет. Шумом считаются
метки `.fetched`, календарь над журналом WB, версия генератора и пути сборки ЯМ,
а также переезд страниц при переименовании раздела. Если упал источник, придёт
короткое предупреждение: без него молчание нельзя было бы отличить от «ничего не
поменялось». Новая площадка в зеркале приходит одной строкой, а не списком
из десятков «новых страниц».

Включается, только когда задан бот, иначе шаг молча пропускается:

```json
// ~/.config/mp-docs/config.json
{"telegram": {"bot_token": "123:ABC…", "chat_id": "123456789"}}
```

или переменными `MP_DOCS_TG_BOT_TOKEN` и `MP_DOCS_TG_CHAT_ID`. Сводка строится по
git-истории зеркала от последнего отправленного коммита (`state/notify.json`), так что
неудачная отправка ничего не теряет: находки уедут со следующим прогоном.

```bash
bin/mpdocs notify --dry-run                 # что ушло бы сейчас, без отправки
bin/mpdocs notify --since HEAD~3 --dry-run  # сводка за последние три обновления
bin/mpdocs update --no-notify               # обновить, не сообщая
```

## Зачем зеркало, а не поход в сеть каждый раз

1. **Скорость.** Страница Ozon или WB через браузер с резидентного канала — ~60 с.
   Поиск по зеркалу — мгновенно.
2. **История, причём двумя способами.** Маркетплейсы ведут свои журналы обновлений,
   и все они в зеркале — `mpdocs changelog`:

   | Площадка | Где журнал | Объём |
   |---|---|---|
   | Ozon | тег `News` внутри спеки | 212 записей, вся история |
   | Яндекс Маркет | `changelog/{all,main,deprecated}.md` из справки | 540 КБ, вся история |
   | Wildberries | страница `/release-notes` | последние 20 записей, скользящее окно |
   | Uzum Market | журнала нет | только `mpdocs changes` |

   Но объявляют не всё, поэтому зеркало под git ловит и молчаливые правки:
   `mpdocs changes`, то же самое что `git log -p -- ozon/api/seller/`.
   Метод `/v3/posting/fbs/list`, который отключают 31 августа, в журнале не
   объявлен — он нашёлся по флагу `deprecated` в спеке.
3. **Офлайн.** Канал может лежать, туннель — отвалиться. Справочник от этого не зависит.

## Что откуда берётся

| Источник | Механика | Цена обновления |
|---|---|---|
| **Ozon Seller API** | `docs.ozon.ru/api/seller/` — это Redoc, спека OpenAPI приходит одним XHR (~4 МБ, 460+ методов). HTML не парсится вообще. | ~1 мин |
| **База знаний Ozon** | `seller-edu.ozon.ru`: текста в DOM нет, статью отдаёт `document-manager` API вместе со списком детей. Обход дерева и получение текста — один и тот же запрос. | ~10 мин |
| **Wildberries** | 13 разделов `/docs/openapi/*`, в каждом спека лежит инлайном в `const __redoc_state` внутри страницы. | ~5 мин |
| **Яндекс Маркет** | Антибота нет. У каждой страницы есть markdown-двойник (`.md`), список всех — в `llms.txt`. Спека OpenAPI — в официальном репозитории на GitHub. | ~3 мин |
| **Uzum Seller API** | Антибота нет: `api-seller.uzum.uz/api/seller-openapi/swagger/api-docs` отдаёт спеку одним JSON. Авторизацию и лимиты спека описывает только схемой и заголовками — они вынесены в `guides/avtorizaciya-i-limity.md`. | ~1 с |
| **Инструкция Uzum** | `seller.uzum.uz/manual` — VuePress за «проверкой браузера» Яндекса, Camoufox проходит её с серверного IP. Список страниц — из siteData в `app.*.js` (скрипты антибот не закрывает), вместе со скрытыми. Узбекская версия не берётся: это перевод тех же страниц. | ~30 с |

Разделы WB и корневые разделы базы знаний Ozon **не зашиты в код**, а вычитываются
на каждом прогоне: появится новый — попадёт в зеркало сам.

## Устройство

```
bin/mpdocs              лаунчер (сам находит подходящий python)
install.sh              установка на новую машину
skill/SKILL.md          инструкция для агента (шаблон, пути подставляются при установке)
scripts/
  common.py             пути, frontmatter, запись «только если изменилось», git
  render_openapi.py     OpenAPI → markdown, по файлу на метод
  bundle_openapi.py     сборка многофайловой спеки (ЯМ) в одну
  src_ozon_api.py       спека Seller API
  src_ozon_kb.py        обход seller-edu
  src_wb.py             13 разделов WB
  src_ym.py             справка + спека ЯМ
  src_uzum_api.py       спека Seller API Uzum
  src_uzum_kb.py        инструкция для продавцов Uzum
  mcp_server.py         MCP поверх зеркала (JSON-RPC по stdio, без зависимостей)
  notify.py             сводка «что нового» в Telegram по git-истории зеркала
  mpdocs.py             CLI
mirror/                 само зеркало — ОТДЕЛЬНЫЙ git-репозиторий
state/                  кеши обхода, чекаут спеки ЯМ (не в git)
```

`mirror/` — отдельный репозиторий намеренно: в его истории только изменения
документации, без правок качалок. Иначе `git log` бесполезен.

`fetched_at` не участвует в сравнении содержимого — иначе каждый ночной прогон
давал бы дифф по всем файлам.

## Ограничения

- Markdown метода — читаемый срез с ограничением глубины вложенных схем.
  Спорные детали сверять с `spec.json` рядом.
- У WB в зеркале только последние ~20 записей журнала: страница отдаёт скользящее окно.
- На машине-источнике Camoufox один на всех и под общим flock с другими сервисами,
  поэтому зеркало обновляется раз в сутки ночью, а не по требованию.

## Права

Код — наш. Содержимое `mirror/` принадлежит Ozon, Wildberries, Яндекс Маркету и Uzum:
это их публичная документация, скачанная как есть, без правок. Зеркало сделано для
удобства разработки и не заменяет официальные источники — если расходится, право
за официальным.
